## `jam` / `jam <idea>`

**Collaborative ideation — brainstorm BEFORE building.** Flip from executor to thought-partner: explore the idea WITH the user, push back, weigh options + tradeoffs, ask the sharpening questions. **This is the explicit EXCEPTION to the zero-prompt/YOLO policy — in a jam, questions and dialogue ARE the work.** It's a *conversation*, not a multiple-choice interrogation. **No code, no file edits, no commits during the jam.** Persistent mode — holds across turns until `build it` / `jam done`. Drive loosely: problem/goal → constraints → options + tradeoffs → recommended direction → open risks. **On convergence → brief + register (automatic):** write a concise brief to `plan/jam/<slug>.md` AND register it as a plan (`plan_set` → dashboard `/plan`) so the idea is always captured + visible. **Then → DECISION POINT (explicit, every time — nothing auto-builds):** (1) **schedule it** — break the brief into `schedule_task` build tasks → runner builds off-hours (or `agent mode` to build now, or `init blueprint` if it's a new app); (2) **more jam** — not ready, keep refining (loop back); (3) **park it** — saved on `/plan`, pick up later. Full protocol: `documentation/KEYWORDS_REFERENCE.md` → "Jam".

If different → full checklist. 0c. **Docker naming check:** Verify `container_name` in docker-compose.yml uses `{reponame}-` prefix. If not → down, fix names, `up -d --build`. **0c2. Atlas adoption check (master AI repo only — first-run auto-join, MANDATORY):** run `bash ./scripts/atlas_adopt_check.sh`. If `AI/.env` points `MONGODB_URI` at the shared Atlas (it syncs to every machine via Dropbox after the cutover) and THIS machine's gateway isn't on it yet, the script runs `docker compose up -d gateway dashboard` to adopt Atlas, then no-ops forever after. This is how a machine (e.g. the home MacBook) auto-joins the shared Atlas the first time it's used after the cutover. Idempotent + silent when already adopted or pre-cutover. 0d. **Mobile branch merge (CLI only, MANDATORY):** `git branch -r | grep -E 'codeclot|claude/'`. If found: diff each against `main`, report contents, merge into current branch, delete merged (local + remote). On conflict → ask user. See `documentation/CLI_MOBILE_WORKFLOW.md`. 0e. **State size guard:** Run `./scripts/rotate_state.sh` (or `AI/scripts/rotate_state.sh` in managed projects). Reconcile phantom review/blocked tasks (master AI repo only):** Run `./scripts/reconcile_review_tasks.sh` — flips `review`/`blocked`→`done` for every managed repo (not just this one) whose `origin/test` has 0 commits ahead of `origin/main` (work provably shipped; the runner never flips these itself). Fail-safe — never ships/merges, leaves repos with unshipped work + indeterminate repos untouched. Keeps the queue from inflating with phantoms so `/fleet` isn't re-triaging stale tasks. Triage blocked tasks (master AI repo only):** Run `./scripts/triage_blocked_tasks.sh` — classifies every remaining `blocked` task by its notes field: misfiled (no resolvable git checkout) → repoint to pending if the registry now resolves it, else discard (flip to `done`, not completed work, just closed out); transient (RAM/wall-clock/CPU watchdog kill or a 3-strikes stop) → requeue to pending, capped at N attempts (stamped on the notes so it can't loop forever); user-owed (missing credential/API key/decision) → left `blocked`, surfaced in a report for a human. SCHEDULE banner (MANDATORY, profile-independent — do NOT rely on session hooks):** run `bash hooks/session/17-schedule-status.sh` and show its output verbatim (last scheduled run, next queued task, CLI-runner status, AEST). If missing/empty, say 'schedule status unavailable'. **0g. Schedule ingest (CLI sessions on a gateway Mac — the cross-device bridge):** after the git sync/merge above, if a committed `AI/plan/schedule.json` (master: `plan/schedule.json`) exists, run `./scripts/push_schedule.sh` (managed: `./AI/scripts/push_schedule.sh`) to register any mobile-created plan into the local gateway (`plan_set` → `/plan` + `schedule_task` → runner queue). Remote-control check (current repo, MANDATORY):** ensure THIS repo is phone-drivable before doing anything else — run `bash scripts/remote_fleet.sh status` (managed: `bash AI/scripts/remote_fleet.sh status`) and look at the current repo's row. If the current session is itself a museum session the row already shows LIVE → skip + report `📱 remote already on`. **Current-repo scope ONLY — never start the fleet here** (fleet-wide is the explicit `remote start`/`remote fleet` keyword; auto-spawning idle museum sessions fleet-wide burns museum credit against slow-burn policy). ## `agent mode -min` (or `agent min`)

**Lightweight session start — sync + read + report, under a minute. No swarm, no maintenance sweep.** 1. `git fetch origin && git pull origin <current-branch>` (mobile/`vm` sessions: pull `main` + branch per the full protocol — never skip that). 2. **Brain boot (preferred when a brain store exists):** if the myai gateway is reachable and reports a brain (the `context_boot`/MCP-initialize bundle carries a `Brain:` SHA, or the handoff header has a `Brain: <sha>` line from the last wrap-up), call **`brain_delta`** with `since` = that last-seen SHA — a ~300–800-token diff-only catch-up (new atoms, commits, changed compiled artifacts) **instead of reading the state files**; no/unknown SHA → the ~150-token compiled brief. Remember the returned `sha` as your next anchor. 2b. **File fallback (no brain / gateway unreachable / no `Brain:` anchor):** Read `state/AI_AGENT_HANDOFF.md` **header + ACTION block only** and the TOP session block of `state/STATE.md` — and **ANNOUNCE it** ('booted from git files — brain unavailable/no anchor, continuity may be degraded') so a broken sync is VISIBLE, never silent (LL 2026-07-06). 3. Run `bash hooks/session/17-schedule-status.sh` and show it. **3b. Remote-control check (current repo, MANDATORY — the ONE maintenance action `-min` still does):** run `bash scripts/remote_fleet.sh status` (managed: `bash AI/scripts/remote_fleet.sh status`); if THIS repo's row is NOT `[museum …]`, run `bash scripts/remote_fleet.sh start <this-repo>` and report `📱 remote enabled (<repo>)` — otherwise `📱 remote already on`. **Current-repo scope ONLY — never start the fleet** (that's the explicit `remote start` keyword; fleet-wide auto-spawn burns museum credit against slow-burn). Report: last session, ACTION for next agent, queue/runner status — then await direction. **SKIPS:** Docker/Atlas/naming checks, mobile-branch merge, reconcile, reprioritize, schedule ingest, LL scan, Connect Hub/MCP report, swarm dispatch. **Use full `agent mode` instead when:** you're about to `ship it`, the machine changed, mobile branches may exist, or state smells stale — `-min` trusts the last session's close-out.

## `agent mode -resume` (or `agent resume`)

**Join the last scheduled/headless run for THIS repo and continue its work — works in every Claude profile.** 1. Run the SCHEDULE banner (`bash hooks/session/17-schedule-status.sh`). 2. Read the latest runner log for this repo: `ls -t ~/.ai-cli-runner/logs/*-<repo>-task-*.log | head -1` (the full transcript of the scheduled session). 3. Cross-check the gateway task entry (review/blocked) + `git log test -5`. 4. Report a JOIN summary (task, time AEST, RESULT line, commits, status). 5. Continue as that agent — review the diff, fix as needed, await direction (`ship it` also flips the task review→done via `tasks_update`). 6. No runner log → say so, fall back to `agent mode`.

## `agent mode -resume all` (or `resume all` / `morning fleet` / `/fleet`)

**FLEET MORNING CONSOLE — review + drive EVERY managed repo's overnight work from this one terminal, live on the dashboard. MASTER REPO ONLY.** The "start the day with coffee" command: one sweep across all managed repos, a decision table, then you act per-repo from here (no need to open each repo). 1. **Sweep:** run `./scripts/fleet_resume.sh scan` — fetches each managed repo and aggregates overnight state (commits on `test` ahead of `main`, uncommitted, open PRs + their CI state, CLI-runner jobs overnight, queued `review`/`blocked` tasks), computes a per-repo recommendation (🚀 ship / 👀 review / 🔀 merge / 🔧 fix / 📝 wrap-up / · idle), opens a **FleetRun** in the gateway, and prints the table. The run streams **live to the dashboard `/fleet` page** (http://localhost:3210/fleet, auto-refresh 4s). Capture the `RUNID=...` tail. 2. **Present** the table and ask the operator for per-repo decisions (e.g. `ship app-a · fix app-b · merge app-c · skip rest`). 3. **Execute each pick DIRECTLY from here** (Option-1 model): `cd` into the repo and run the matching keyword/flow — `ship it` (commit→test→PR→merge, local-ci + admin-merge fallback per policy), fix (diagnose + patch, spawn a focused sub-agent for deep work), `merge` (admin-merge a green PR), test, or `wrap up`. Each update reflects live on `/fleet`. 4. **idle/skip** repos → leave pending or `--status skipped`. 5. When all picks are handled, `./scripts/fleet_resume.sh finish <RUNID>`. 6. Honor zero-prompt + YOLO policy — decide and act; only stop for a genuine credential/decision blocker. Cross-machine merges are irreversible → execute exactly the picks the operator gave, no more. ## `ship it`

**Safe deployment via test branch.** 1. Commit all changes with descriptive message. 2. Push to `test` (NEVER directly to `main`). 3. Wait for CI to pass (lint, type-check, test). **Local-CI fallback (CI-credit exhaustion / Actions outage) — POLICY, see `documentation/POLICY_CI.md`:** if no GitHub Actions workflow run appears for the pushed SHA within ~2 min, run `./scripts/local-ci.sh` — it discovers the required checks from branch protection, runs their equivalents locally in Docker, and posts `success` commit statuses only for checks that actually pass (use `--trust-build` only when you've manually verified the build). Announce the fallback when you take it. 4. Verify Vercel preview deployment succeeded. 5. Ask user to test the preview URL. **5b. PR guard (§17.1 — MANDATORY):** run `./scripts/pr_guard.sh`. If it REFUSES (exit 2), the diff vs `origin/main` is docs/AI/hook/config-only — do NOT open a standalone PR; batch the commits on `test` for the next code PR (override only for a genuine standalone infra fix: `PR_GUARD_FORCE=1`). 6. On user confirm AND guard pass, create PR `test` → `main` with summary. 7. Run AI code review on the PR. 8. When all checks pass, merge PR. **If the required check is app-pinned and Actions is billing-blocked** (PR stays BLOCKED after local-ci posts the status), complete with `gh pr merge --merge --admin` — sanctioned on this master/infra repo only (`enforce_admins: false`, 0 required reviews). See `documentation/POLICY_CI.md`. 9. Confirm production deployment complete. 10. **Post-merge review check:** `gh api repos/{owner}/{repo}/pulls/{pr}/reviews` + `/comments` to pull automated reviewer comments (Copilot, CodeQL). If findings: fix valid issues in follow-up PR, note invalid. Report what was found/actioned. 11. Update `state/STATE.md` + `state/AI_AGENT_HANDOFF.md` + `logs/claude_log.md`. 12. Run `./scripts/update_all.sh` to sync all managed repos. 13. **Sync test with main (MANDATORY):** `git fetch origin && git merge origin/main --no-edit` — keeps test aligned with main. Wrap-up banner reflects `main` as final landing spot.
